### scripts/prepare_jvs_mix.py — JVSの2話者混合音を作る(新規)

- 考え:
  - 2段階の構成(①16k→8kのキャッシュ作り → ②混合音の生成)にした。変換は全12,997発話に対して1回で済ませられ、混合の条件を変えて生成をやり直すときに再変換が要らない。キャッシュにはパスとサンプル数の対応(index)を持たせ、2回目以降は音声を読まずに長さで絞り込める
  - SNRのかけ方: 話者1はそのまま、話者2だけをスケールする。音が大きくなりすぎるのを防ぐ処理は「すべての信号を同じ比率でスケールする」にした。話者1・話者2・混合音を別々に正規化すると、混合音=話者1+話者2という関係とSNRが崩れ、評価が狂うため
  - 短い方に合わせて完全に重なる混合にした。TF-Locoformerの論文でのWSJ0-2mix系の標準(min版)に合わせた
  - 学習・検証・評価それぞれで乱数の種をずらして固定する(学習:+0、検証:+1、評価:+2)。同じ種での再実行は同じデータを作り直す(毎回同じ結果になる)
- 検証: 20件の混合音での簡易確認で、混合音−(話者1+話者2)の最大の誤差が0であること、実測したSNRが記録と一致すること、8kHzで出力されることを確認した

### scripts/download_teacher.sh — 教師のチェックポイントを取得する(新規)

- 考え: MERLのリポジトリにある学習済みの.pthファイルはGit LFSで管理されており、通常は`git clone`と`git lfs pull`で取るのが筋である。しかしNAS(NFSv3)上では`git clone`が失敗し、ローカルディスクは満杯(DEC-009)でクローン先もない。そこで、コード本体はGitHubのtarball展開で取得し(gitのオブジェクトを使わない)、LFSのポインタファイル(実体のIDとサイズが書かれたファイル)からLFSのbatch APIを直接呼んで実体をダウンロードする方式にした
- 安全策: ダウンロードのあとにファイルサイズを照合し、一致しなければ失敗させる。すでに実体化済みのファイルは飛ばす(何度実行しても同じ結果になる)
- 結果: 5つすべてのチェックポイント(WSJ0-2mix / Libri2mix / WHAMR!のMediumとSmall / DNS)を実体化した。WSJ0-2mix版(Medium、パラメータ数15.0M)の重みの読み込みを確認した

### scripts/eval_separation.py — PIT + SI-SNR(改善量)での評価(新規)

- 考え:
  - 推論はESPnetの`SeparateSpeech`を使う。教師のチェックポイントはconfig.yamlと一緒になったESPnetの形式なので、自分でモデルを組むより設定ミスのリスクが小さい。E0(教師)とE1-E3(生徒)で同じ評価コードを使うことで、実験どうしの比較を公平にする
  - SI-SNRは数式どおり自分で実装した(数十行)。mir_evalなどへの依存を増やさない。PITは話者が2人なので、2通りの組み合わせを総当たりで比べる
  - SI-SNRの改善量は「入力の混合音をそのまま推定結果とみなしたときのSI-SNR」を差し引いて計算する。ファイルごとのCSVと、平均・中央値・標準偏差をまとめたJSONを出力し、発表用の箱ひげ図を後から作れるようにした

- 考え: ルートの記憶領域が満杯(空き199MB、主な原因は他ユーザー)で、ローカルにはデータもチェックポイントも置けない(DEC-009)。リポジトリ内の相対パス(`data/...`)をそのまま保ちながら実体をNASに置くため、ディレクトリの本体ではなくシンボリックリンクにした。コードはパスの違いを意識しなくてよい

### scripts/prepare_jvs_mix.py — 雑音を加える対応(DEC-010) (2026-07-20)

- 背景: E0で英語教師がクリーンな日本語混合音を追加学習なしでSI-SNR改善量25dBほど分離してしまい、適応の余地がないと判明した。適応先をWHAM! noiseつきの混合音に難しくする(DEC-010)
- 考え:
  - 設定ファイルに`noise:`という項目があるかどうかで、同じスクリプトがクリーン版・雑音版の両方に対応するようにした。クリーン版を作り直した結果は従来とまったく同じになる(後方互換)
  - 雑音のSNRはWHAM!の設定にならい、「大きい方の話者のパワー」を基準にした一様分布[-6,+3]dB。雑音の素材はWHAM!の学習・検証・評価の分け方を、本プロジェクトの学習・検証・評価に対応させ、重ならないようにする
  - 雑音専用の独立した乱数(種+1000)を使う。乱数を教師データの抽選と共有すると、雑音のための乱数消費が後続の話者ペアの抽選をずらしてしまい、クリーン版と混合の並びが一致しなくなるため。同じ種のクリーン版と「同じ話者ペア・同じ話者間のSNRで、雑音の有無だけが違う」比較ができるようにした
  - 雑音はステレオの1チャンネル目を使う(WHAM!の1チャンネルタスクの慣例)。短い場合はタイルして、ランダムな位置から切り出す。`noise/`という下位ディレクトリにも保存し、確認やE4に使えるようにした

### remixit/training.py, scripts/train_supervised.py, scripts/train_remixit.py — 途中から再開する機能を追加 (2026-07-23)

- 背景: セッションの再起動を何度かはさんだあと確認すると、E1・E2ともプロセスは生きているのにGPU使用率が0%で約21時間止まっていた(詳細: DEC-014)。再起動すると最初からやり直しになり損失が大きいため、先に再開機能を作った
- 考え:
  - `save_checkpoint`に`**extra`を追加し、最適化手法・学習率スケジューラの状態を任意で追加保存できるようにした。書き込み中に落ちても既存ファイルを壊さないよう、一時ファイルに書いてから置き換える方式にした
  - `--resume`で読み込む際、最適化手法・学習率スケジューラの状態が無い場合(修正前に保存された古い形式のチェックポイント)にも対応できるよう、無ければ初期値で補う作りにした。学習率スケジューラだけは、位置がずれないよう再開後のエポック数ぶん空回しして合わせ直す
  - 教師を逐次更新する設定(E3)では、教師の重みもチェックポイントに含め、再開時に正しい教師の状態を復元できるようにした
- 検証: 小さな模擬データで「保存→再開→続きから学習」が正しく動くことを、新しい形式・古い形式のチェックポイントの両方、E1・E2の両スクリプトで確認した
- 適用結果: 実際に止まっていたジョブ(E1はエポック26まで完了、E2はエポック11まで完了していた)を止めて、この機能で再開した。GPU使用率は両方とも98〜99%に復帰した

### scripts/train_remixit.py — 早期終了を追加した(E2の所要時間の見積もり違いの修正) (2026-07-20)

- 問題: E1・E2の学習を始めて1.5〜2時間後、W&Bの記録から実際のペースを確認したところ、E2が1エポックあたり約183分だと判明した。当時の設定(`epochs:60`、早期終了なし)のままだと、E2だけで約7.6日かかり、発表の期限に間に合わないことが分かった(詳細: DEC-013)
- 考え: E1には早期終了を実装していたのに、E2に入れ忘れていたのは単純な抜け漏れだった。ただしE2/E3は「教師の更新」がある分E1より複雑で、E1のやり方をそのままコピーすると、教師を逐次更新する設定(E3)でうまく動かない: 教師が変わると検証損失の意味(教師との一致度)がリセットされるため、教師の更新をまたいで「これまでの最良値」を比べると、そのときの教師の良し悪しに引きずられ、正しく収束を判定できない。そのため、教師を更新するたびに最良値と改善のない回数をリセットするようにした
- 設定の変更: `epochs`を60から30に(RemixITの元論文でも改善の大半はエポック20〜40で頭打ちになる)、早期終了の許容回数を8に追加、教師の更新間隔を20から15に(epochsの縮小に合わせて)
- 運用の教訓: 学習ジョブを始めたら、最初の1エポックが終わった時点でW&Bの実際のペースを確認し、設定のエポック数×実際の時間が期限に収まるか計算し直す運用にする
- プロセスを止める際の注意点: `conda run -n ... python script.py &`で始めたジョブを止めるとき、`kill <conda runのプロセス番号>`だけでは実体のpythonプロセス(とデータ読み込みの子プロセス)が終わらない。`ps aux`で実体のプロセス番号を確認し、`nvidia-smi --query-compute-apps`でGPUのメモリが実際に解放されたことを確認してから次のジョブを始める必要がある(今回、最初のkillで子プロセスが残っていることに気づかず、追加の確認が必要になった)

### W2の中核実装: remixit/ パッケージ + 学習スクリプト (2026-07-20)

- remixit/remix.py: バッチ内での混ぜ直し。入れ替えは「自分自身とは入れ替わらない並べ替え」からサンプルする。自分自身と混ざると「教師推定の和がほぼ元の混合音のまま」になり、学習の手がかりが弱くなるため
- remixit/datasets.py: 混合音だけを使うデータセットのクラスは`mix/`しか参照しない作りにした(RemixITが正解に触れないことをクラスの作りそのもので保証する)。テストで、話者1・話者2のファイルへのアクセスがないことを確認する
- remixit/losses.py: 2話者のPIT+負のSI-SNRを自分で実装した(2通りの組み合わせを総当たり)。ESPnetの損失クラスへの依存を避け、混ぜ直しの損失と評価で同じ実装を使う
- remixit/separator.py: 教師(MERLのモデルから構築)と生徒(自分の設定からゼロから構築)を、同じ波形の入出力を持つラッパー`SeparationModel`にまとめた。RemixITの逐次的な教師更新は生徒の重みをそのままコピーする形で実現する(教師と生徒でモデルの構造が違っても成立する。RemixITの論文でも生徒で教師を置き換える方式を使っている)
- remixit/training.py: 学習率を最初上げてから徐々に下げるスケジューラ(jchat-sepの教訓: 最初から自動化する)、自前のチェックポイント形式、W&Bの初期化
- scripts/train_supervised.py(E1)/ train_remixit.py(E2/E3): 1つのスクリプトが1つの実験を担う。RemixITの検証損失は「教師との一致度」であり、おかしくなっていないかを見るためだけに使うと説明文(docstring)に明記した。教師を固定するか逐次更新するかは設定ファイルで切り替える
- バッチサイズの実測(2080 Ti 11GB): バッチサイズ4×4秒はメモリ不足、4×3秒もメモリ不足(10.6GB)、2×4秒なら動く。バッチサイズ2+勾配の蓄積2(実質バッチサイズ4)で確定した。バッチサイズが2でも「自分自身とは入れ替わらない並べ替え」は成立し(=入れ替わる)、エポックごとにバッチの組み合わせが変わるため、混ぜ直しの多様さはステップを重ねることで確保される
- eval_separation.py: `--student_ckpt`を追加し、教師(ESPnet形式)と生徒(自前形式)を同じ評価の経路で比べられるようにした
- 簡易確認: E1・E2ともGPUで数ステップの学習が通ることを確認した。テスト6件が通った

### remixit/espnet_compat.py — TF-Locoformerを実行時に登録する(新規)

- 問題: 教師のチェックポイントのconfig.yamlは`separator: tflocoformer`を指定するが、環境にあるESPnet 202402の登録先(`separator_choices`)にtflocoformerが登録されておらず、`SeparateSpeech`の構築がエラーで失敗した(モジュール自体は環境にある)。MERL公式の手順は`espnet2/tasks/enh.py`へのパッチ当てである
- 考え: ESPnet本体は書き換えない方針(05_architecture.md)のため、パッチではなく実行時の登録にした。`separator_choices.classes`はただの辞書なので、互換用のモジュール`remixit/espnet_compat.py`を読み込むときに1件追加するだけで済む。ESPnetを入れ直しても壊れず、何をしているかがコード上ではっきり分かる
- 使い方: モデルを構築する(SeparateSpeech / build_model)より前に`import remixit.espnet_compat`する
